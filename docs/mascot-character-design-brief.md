# 猫与蜘蛛：原创角色制作简报

> 用途：交给图片生成工作流 AI、角色原画师或像素动画制作流程，作为统一的角色圣经。\
> 目标：生成可长期复用的原创位图角色，而不是一次性的装饰插图。

## 1. 核心概念

这是一组围绕 `ZZW`、`Zw`、`Zw-awa` 和 `web` 延伸出来的搭档形象：一只猫和一只蜘蛛。

- **猫负责上限**：决定什么值得做、往哪里走、怎样才算漂亮和有意义。
- **蜘蛛负责下限**：保证事情能持续、资源不会断、细节不会丢、承诺一定落地。
- **关系公式**：`1 + 1 >> 3`。两者不是主人与仆人，而是能力互补、彼此依赖的平等搭档。

最重要的叙事不是“猫很聪明、蜘蛛很勤劳”这两句标签，而是让画面表现出：

> 猫决定去哪里，蜘蛛保证走得到。\
> 猫决定什么值得留下，蜘蛛保证它不会丢失。\
> 猫负责意义、审美和方向，蜘蛛负责连接、资源和连续性。

## 2. 整体视觉目标

### 期望气质

- 原创、亲和、聪明，有一点调皮和不按常理出牌。
- 像高质量游戏中的 2D 像素角色：轮廓清楚，缩小后仍可识别，放大后有丰富细节。
- 画面可以华丽，但角色本身必须先读得清楚；装饰不能抢走角色的戏。
- “现代化、好用、可复用”：优先制作透明背景母版，再派生网页桌宠、加载动画、图标和动作帧。

### 统一画风

- 高密度、干净的像素插画；像素边缘有秩序，不是随机马赛克。
- 清晰外轮廓，适度深色描边，内部使用成组色块和少量高光。
- 柔和但明确的体积光，避免塑料感和过度写实的毛发/昆虫细节。
- 保留手工感的小巧思：不对称的小动作、会变化的眼神、偶尔多余但可爱的道具。
- 默认透明背景，不要把角色固定在复杂场景中。

### 输出基础

- 交付格式：透明 PNG，保留完整轮廓，不要水印、文字、Logo 或背景阴影。
- 猫母版建议 `256 x 256 px`；网页显示通常为 `96–128 px`。
- 蜘蛛母版建议 `128 x 128 px` 或 `256 x 256 px`；网页显示通常为 `32–64 px`。
- 角色应有安全留白，四肢、尾巴、蛛丝不能贴边，以便后续裁切和动画。
- 先生成单张静态母版并确认造型，再生成动作帧；不要一开始就生成整张精灵表。

## 3. 角色 A：猫（Zw / ZZW）

### 角色定位

猫是这个世界观中的“想法、判断和审美”。它拥有极高的理解力，却不热衷于处理琐碎事务。它不懒得思考，反而思考得太快、太远；它只是认为很多执行工作不值得亲自起身。

### 性格关键词

**正向特质**

- 慵懒、随性、惬意
- 极高智商，观察力强，能迅速抓住本质
- 审美敏锐，喜欢简洁但有巧思的东西
- 有好奇心，偶尔故意恶作剧来测试周围的人
- 在关键时刻果断，能做最终选择

**不完美之处**

- 自理能力较弱，容易把生活细节弄得一团糟
- 不喜欢重复劳动、填表、整理和收尾
- 有时过度自信，低估了执行成本
- 可能突然改变兴趣，把蜘蛛留在半路收拾残局

这些缺点要让它更可爱、更真实，而不是让它变成无能或傲慢的反派。

### 行为与表情

- 常见姿态：蜷坐、侧躺、尾巴绕身、单爪托腮、半睁眼观察。
- “聪明”通过眼神表达：看向远处、斜视、突然聚焦、发现关键点时眼睛变亮。
- “慵懒”通过重心表达：肩背放松、动作幅度小、四肢不完全收整齐。
- “调皮”通过细节表达：用爪子拨弄蛛丝、把重要物品压在身下、故意指错方向后偷笑。
- 不要长期使用夸张咧嘴笑；更适合微妙的嘴角、耳朵角度和尾巴动作。

### 颜色与主题变体

橘猫是默认、经典、对外识别度最高的版本：

- 主色：暖橘、橘黄、浅奶油色。
- 条纹：少量、清楚、具有像素块面，不要画成写实虎斑。
- 眼睛：明亮的青绿色或黄绿色，作为识别焦点。

黑猫是深色模式的对应版本，不是另一个角色：

- 保持与橘猫完全一致的轮廓、比例、姿势和表情库。
- 主色：黑灰或深炭色，保留可读的冷暖层次，不能糊成纯黑剪影。
- 眼睛：明亮的金黄或琥珀色。
- 高光可以偏冷蓝灰，让深色模式下仍有体积和轮廓。

### 建议动作帧

- `idle`：尾巴缓慢摆动，耳朵偶尔动一下。
- `blink`：眨眼后保持原本慵懒姿势，不要整张图跳动。
- `sleep`：身体收拢，出现极小的呼吸起伏或鼻尖气泡。
- `thinking`：一只爪子托腮，眼睛跟随漂浮的想法/光点移动。
- `mischief`：拨动一根蛛丝或藏起一个小物件，回头观察蜘蛛反应。

## 4. 角色 B：蜘蛛（Web）

### 角色定位

蜘蛛是这个世界观中的“资源、网络和可靠执行”。它们可以是一只，也可以是一群协作的蜘蛛。蜘蛛不负责提出宏大创意，却拥有无穷无尽的连接、资料、工具和耐心，能够把猫的想法变成现实。

### 性格关键词

**正向特质**

- 勤劳、忠诚、肯干、可靠
- 有极强的持续工作能力和耐心
- 擅长连接、收集、分类、修补、搬运和归档
- 对猫的指令反应迅速，但不会盲目抢功
- 即使没人注意，也会把基础工作维护好

**能力边界**

- 几乎不会主动提出方向或意义判断
- 不擅长审美选择，容易把“能用”误认为“好看”
- 面对开放问题会停顿，等待猫给出目标
- 数量很多时会显得忙乱，但仍然努力保持秩序

蜘蛛的“不会出谋划策”不是愚蠢，而是分工明确：它知道自己的价值在于让可能性持续存在。

### 行为与表情

- 常见姿态：快速爬行、悬挂、拉线、搬运小物件、修补断裂的网。
- 可用眼睛数量和亮点表达情绪，但不要做成恐怖昆虫特写。
- 开心：动作变快，蛛丝形成整齐的弧线。
- 困惑：几条腿停在不同方向，身体微微倾斜，等待猫确认。
- 忠诚：始终让一根蛛丝连接到猫或核心物件，像一条可靠的回路。
- 忙乱：多只蜘蛛同时工作，画面有节奏但不凌乱失控。

### 造型方向

- 采用可爱、简化、偏像素游戏宠物的比例；身体略圆，腿部关节清楚。
- 腿可以修长，但要有明确色块和圆润末端，避免尖锐、湿润、写实的恐怖感。
- 颜色以深灰、墨黑、暖棕为主，可用青色或橘色微光与网站主题呼应。
- 蛛网是它的“工具和资源网络”，线条要整齐、具有结构感；不要把画面填满密集网格。

### 建议动作帧

- `idle`：身体轻微上下浮动，腿部依次调整。
- `step-a / step-b`：两组腿交替迈步，适合循环爬行。
- `weave`：拉出一根线，绕过节点，再回头检查连接。
- `carry`：搬运小书、钥匙、文件、星星碎片等象征资源的物件。
- `repair`：发现断线后立即补网，完成后短暂停顿确认成果。

## 5. 两者同框时的表达

两者同框时，画面应体现“猫给方向，蜘蛛给结构”，而不是简单让蜘蛛站在猫旁边。

### 推荐构图

- 猫在视觉焦点或较高位置，姿态放松，指向一个目标、星点或远处出口。
- 蜘蛛在下方或周围铺设路径、连接节点、搬运材料，让猫指向的目标变得可达。
- 猫可以踩着一小段蛛网休息，但蛛网必须看起来是蜘蛛主动搭建的可靠支撑。
- 多只蜘蛛可以形成有秩序的群体节奏，数量增加代表资源增加，不代表角色等级变化。
- 留出明显的视线动线：猫的视线/爪尖 -> 目标；蜘蛛的蛛丝/路径 -> 猫和目标之间。

### 推荐互动

- 猫指向一颗星或一扇门，蜘蛛在旁边迅速织出桥。
- 猫把一枚重要徽章压在身下，蜘蛛从网中找出备用方案。
- 猫躺在网中央思考，蜘蛛围绕它整理资料和工具。
- 猫露出“我早就知道”的表情，蜘蛛完成最后一个连接后疲惫但满足。
- 猫偶尔拨乱一根线，蜘蛛无奈修好；这种小冲突能体现亲密关系。

### 避免的关系表达

- 不要让蜘蛛看起来像被猫奴役或被踩在脚下。
- 不要让猫永远高高在上、表情冷漠；它应当依赖并在意蜘蛛。
- 不要让蜘蛛变成会讲话、会发明宏大策略的第二只猫。
- 不要在画面中直接写出“上限/下限/1+1>>3”等说明文字；用动作和构图表达。

## 6. 适合网站的场景化使用

### 加载页

加载页只使用蜘蛛即可，保持短暂、轻量和易读：

- 一只蜘蛛沿着逐渐生成的蛛丝前进。
- 蜘蛛修补一个断开的节点，节点连接后加载完成。
- 多只小蜘蛛从不同方向搬来光点，最后汇聚成一个稳定的核心。

加载动画不需要出现猫。猫是“方向和最终选择”，不必在每次短暂等待中出场。

### 桌宠

桌宠以猫为主，蜘蛛作为偶尔出现的小配角：

- 猫在屏幕角落睡觉、发呆、观察光标，偶尔做出聪明但没必要的恶作剧。
- 当页面有后台任务、同步或加载时，一只小蜘蛛可以从猫身后出现并开始工作。
- 深色模式使用黑猫；浅色模式使用橘猫。行为逻辑相同，只改变配色和眼睛。

### 页面装饰与彩蛋

- 在卡片、按钮或进度轨迹附近放置极小的蜘蛛和蛛丝，作为可发现的彩蛋。
- 猫可以偶尔压住进度条、拨动游标或把一个图标推开，但不能妨碍核心操作。
- 装饰动画应支持 `prefers-reduced-motion`，减少运动时保留静态姿态和必要反馈。

## 7. 图片生成正向提示词模板

以下模板用于生成单个角色母版，可根据工作流改写为英文或拆分为节点参数：

```text
原创像素游戏角色，透明背景，单个完整角色，清晰轮廓，干净有秩序的高密度像素块面，
柔和体积光，少量高光，现代独立游戏美术风格，缩小后仍然易识别，角色周围留出安全边距，
不依赖场景和文字表达性格。

角色：{橘猫/黑猫/蜘蛛}
性格：{慵懒聪明/勤劳可靠/困惑但忠诚}
姿态：{蜷坐/托腮思考/拉线修网/搬运资源}
表情：{半睁眼/微妙得意/专注/完成任务后的满足}
道具：{可选，少量且服务于叙事}
配色：{根据角色变体填写}
```

## 8. 反向约束（必须避免）

```text
无水印，无文字，无Logo，无签名，无背景场景，无地面投影，
无几何图标感，无随机噪点像素，无模糊轮廓，无过度渐变，
无恐怖写实蜘蛛，无尖锐毒牙和血腥元素，无机器人猫，
无塑料3D材质，无照片级毛发，无复杂透视，无裁切四肢和尾巴，
不改变角色比例，不添加多余角色，不把蜘蛛画成主角，不把猫画成反派。
```

## 9. 生产流程建议

1. **角色母版**：分别生成橘猫、黑猫、单只蜘蛛的透明 PNG，先确认轮廓、比例、颜色和脸部识别度。
2. **一致性锁定**：以通过审核的母版作为参考图/图像条件，固定画风、视角、像素密度和光源。
3. **动作拆分**：逐个生成 `idle`、`blink`、`thinking`、`weave` 等动作，不要直接生成长视频。
4. **人工清理**：去除水印和背景残留，修正像素孤点、断线、穿模和不一致的眼睛/条纹。
5. **网页适配**：导出 1x、2x、4x 尺寸，测试浅色/深色模式、移动端和 `prefers-reduced-motion`。
6. **小范围试用**：先把猫用于桌宠、蜘蛛用于加载页，观察识别度和动画循环是否自然，再扩展到更多页面彩蛋。

## 10. 验收标准

- 只看轮廓缩略图，也能分辨猫和蜘蛛。
- 橘猫与黑猫一眼可看出是同一角色的两个主题版本。
- 猫的画面第一印象是“聪明但懒得动”，蜘蛛是“可靠地持续工作”，而不是相反。
- 两者同框时无需文字，也能看出猫在定方向、蜘蛛在搭路径。
- 角色脱离复杂背景仍成立，放在加载页、桌宠和卡片角落都不会显得像临时贴图。
- 动作循环首尾衔接自然，缩小到网页实际尺寸后仍保持眼睛、耳朵、腿和蛛丝的识别点。
